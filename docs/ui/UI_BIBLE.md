# MEGAMI EXPEDITION — UI 바이블

UI 작업(새 화면, 기존 화면 수정, 팝업 하나라도)을 시작하기 전에 이 문서를 먼저 읽는다.
이 문서와 맞지 않는 결정이 필요하면 **구현하기 전에 사용자에게 묻는다**(취향·방향 문제는 에이전트가 혼자 정하지 않는다).

- 레퍼런스: *Metaphor: ReFantazio*의 **방법론**(한 문장 모티프, 화면마다 고유한 구도, 순간을 극적으로 만드는 전환). 메타포의 생김새를 베끼지 않는다.
- 서체 견본: [font-specimen.html](font-specimen.html) (개발 서버에서 `/docs/ui/font-specimen.html`)

---

## 1. 모티프

> **태엽 계기판 위에 여신의 깃털이 내려앉는다.**
> 평소의 UI는 정밀하게 맞물린 황동 기계이고, 결정적인 순간에는 깃펜의 잉크가 칼날처럼 튄다.

| 재질 언어 | 의미 | 언제 쓰나 | 형태 |
|---|---|---|---|
| **기계** (황동 계기판·톱니·태엽) | 원정대의 도구, 통제 | 상시 UI: 파티 카드, 턴 순서, 커맨드 링, 메뉴 | 정밀한 동심원, 눈금, 리벳, 딸깍 끊기는 회전 |
| **잉크** (깃펜 획·튀김·번짐) | 결투, 살기 | 순간: 결정, 공격 명중, 패링, 브레이크, 크리티컬, 스킬 컷인 | 날카로운 사선 획, 튀는 방울, 칼자국처럼 화면을 가르는 선 |
| **깃털** (여신의 흰·금빛 깃털) | 여신의 개입, 축복 | **드물게.** 큰 은총의 순간에만: 영입 성공, 레벨업 | 부드러운 곡선, 천천히 떨어지는 움직임 — 기계·잉크와 대비. 장식·회복·버프에는 쓰지 않는다 |

규칙: **한 요소에는 재질 언어 하나만.** 상시 패널에 잉크 튀김을 넣지 않고, 순간 연출을 계기판으로 만들지 않는다.

## 2. 판단 기준 (모든 시안을 이 4개로 거른다)

1. **이 게임에서만 가능한가** — 다른 판타지 RPG에 그대로 옮겨도 어색하지 않은 구도는 기각한다.
2. **0.2초 안에 읽히는가** — 패링 게임이다. 위험·차례·대상은 장식보다 먼저 읽혀야 한다.
3. **손에 감기는가** — 모든 입력은 움직임 + 소리로 답한다. 무반응 입력은 없다.
4. **스크린샷이 게임 장면인가** — UI 시안이나 웹 대시보드처럼 보이면 실패.

## 3. 색

**고대비 2색 + 예외 2색(진홍, HP 녹색).** 정보 구분은 색 추가가 아니라 명도·크기·반전으로 한다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--ink-0` | `#0b0907` | 바탕 먹색 (가장 어두움) |
| `--ink-1` | `#16120d` | 패널 바탕 |
| `--ink-2` | `#241c13` | 패널 안 구분면 |
| `--gold` | `#d4a83a` | 주 강조색 — 테두리, 선택, 아군 정보 |
| `--gold-hi` | `#f2c94c` | 선택된 항목, 큰 숫자 |
| `--gold-dk` | `#6b5420` | 비활성, 보조 선 |
| `--bone` | `#efe6d2` | 본문 글자 (금빛이 도는 백색 — 별도 색으로 치지 않음) |
| `--bone-dim` | `#8d816c` | 보조 글자 |
| `--crimson` | `#c8283a` | **예외색 1.** 적의 차례·적 공격 예고·받은 피해 숫자·HP 위기(30% 이하)에만 |
| `--hp` | `#5fcf6a` | **예외색 2.** HP 바와 회복 숫자에만 (장르 관습상 가장 빨리 읽힘). 다른 곳에 녹색 금지 |

- 선택 상태 = **반전**(금 바탕 + 먹 글자). 테두리 색만 바꾸는 선택 표시는 쓰지 않는다.
- 패드 페이스 버튼 표기(Xbox A/B/X/Y, PS ✕○□△)는 **기종 고유색을 유지**한다(손이 기억하는 색). 키캡 바탕·테두리만 먹·금. 키보드 키 표기는 먹 바탕 + 금 글자, 둥근 키캡 모양은 유지.
- 속성 아이콘(`icons/el_*`)과 캐릭터 초상은 일러스트이므로 자체 색을 유지한다. 단 UI 프레임·글자색에는 속성색을 쓰지 않는다.
- 회복 숫자는 `--hp`, 버프 표시는 `--gold`. 청록·보라 같은 추가 색은 쓰지 않는다.

## 4. 서체

| 역할 | 서체 | 비고 |
|---|---|---|
| 커맨드·제목·이름 (상시, 기계) | **Hahmlet 800/900** | 사선 적용 |
| 순간 연출 한글 (잉크) | **Gasoek One** | 스킬명 컷인, 한글 대형 배너(선제 공격!, 기습당했다!). 작은 글자에 쓰지 않음(최소 28px) |
| 순간 문구·라틴 제목 | **Cinzel Decorative 900** | **PARRY · BREAK · COUNTER · CRITICAL · WEAK** 같은 잉크의 순간 문구는 영어로. BATTLE · VICTORY · TURN 등 장식 문구도 |
| 숫자 (HP, 피해, AP) | **Cinzel 800** | Decorative는 숫자가 읽기 어려워서 제외 |
| 설명문 | **Hahmlet 400** | **수평 유지.** 14px 이상 |

모두 SIL OFL(상업·게임 사용 가능). Google Fonts로 로드한다.

## 5. 구도 — 전면 사선

- 기본 각도: 패널·띠는 `rotate(-6deg)` 또는 `skewX(-12deg)`. 한 화면 안에서 각도를 2종류 이상 섞지 않는다(주 각도 + 반대 방향 강조 1개까지).
- 기울이는 것: 패널, 띠, 커맨드, 제목, 이름, 숫자.
- **수평 유지: 설명문(문장)뿐.** 한글 장문은 기울이면 읽기 어렵다.
- 화면 중앙(캐릭터와 적이 서는 곳)은 비운다. 상시 HUD는 화면 면적의 25% 이내.
- 패널은 둥근 모서리 대신 `clip-path`로 자른 사선 모서리. 테두리 장식은 9-slice `border-image`(에셋 도착 전엔 CSS 그라디언트 대체).

## 6. 모션

| 토큰 | 값 | 용도 |
|---|---|---|
| `--ease-pop` | `cubic-bezier(.2, 1.5, .4, 1)` · 160–220ms | 등장 (살짝 지나쳤다 돌아옴) |
| `--ease-settle` | `cubic-bezier(.2, .8, .2, 1)` · 200–300ms | 자리 잡기, 이동 |
| `--ease-out` | `cubic-bezier(.6, 0, .9, .4)` · 100–140ms | 퇴장 (등장보다 빠르게) |
| 기계 회전 | `steps()` 또는 짧은 오버슈트 | 톱니가 한 칸씩 **딸깍** 맞물림 |
| 잉크 | 40ms 안에 튀고 400ms 동안 번지며 사라짐 | 순간 연출 |
| 깃털 | 800ms 이상, 좌우로 흔들리며 낙하 | 은총 연출 |

- 상태가 바뀌면 반드시 트윈한다(`display` 즉시 토글 금지). 단 패링 판정 표시처럼 지연이 치명적인 것은 즉시 + 잔상.
- 한 이벤트에 피드백 채널 2~3개(움직임, 소리, 빛·흔들림). 그 이상은 확실히 읽힐 때만.
- 전투 연출은 `Timeline`(`tl.wait`, `tl.tween`) 위에서 돌린다. `setTimeout`·rAF 직접 사용 금지(숨김 패널 테스트, 일시정지와 어긋남).

## 7. 소리

- 커서 이동 `ui_move`, 결정 `ui_ok`, 취소 `ui_back`, 불가 `ui_error`는 **모든** 선택형 UI에 붙인다.
- 톱니 회전에는 딸깍(기계), 잉크 순간에는 베는 소리, 깃털에는 맑은 울림 — 재질 언어와 소리를 맞춘다. 신규 효과음은 `core/audio.ts`의 `SfxName`에 추가.

## 8. 금지 목록

- 둥근 카드(`border-radius` 6px 이상)를 정보 패널에 사용
- 1px 테두리 + 반투명 배경 상자의 반복
- 화면 정중앙 모달에 문단 여러 개
- 웹 버튼 hover(위로 1px, 그림자 번짐), 브라우저 기본 포커스링, 스크롤바 노출
- 우상단 토스트 알림
- 상시 떠 있는 조작법 문단
- 기본 시스템 폰트, Noto Sans KR 단독 사용
- HP·회복 이외의 곳에 녹색 사용

## 9. 화면별 사양

### 9-1. 전투 (첫 샘플 화면)

| 요소 | 결정 |
|---|---|
| 커맨드 | **톱니 링.** 행동 캐릭터 옆에 3D 위치를 추적해서 펼쳐짐. 명령은 톱니 이빨 위치에 배치, 입력하면 톱니가 한 칸씩 딸깍 회전하며 선택. 링 중앙에 AP 계기판. 카메라 구도상 화면 밖으로 나가면 안쪽으로 밀어 넣는다 |
| 하위 목록(스킬·아이템) | 선택한 톱니 이빨에서 **사선 칼날 목록**이 뻗어 나옴. 선택 항목은 금 반전 + 확대. 설명문은 그 아래 수평 띠 |
| 파티 상태 | 좌하단 **사선 초상 카드**. 초상을 평행사변형으로 잘라 겹쳐 배치, HP는 사선 바, AP는 칸 눈금. 행동 중인 캐릭터 카드가 크게 튀어나옴 |
| 턴 순서 | 상단 **사선 띠**. 초상을 평행사변형 칩으로. 현재 차례가 가장 크고, 적 차례 칩은 진홍 테두리 |
| 대상 선택 | 선택된 적 위에 **사선 칼날 표식**이 꽂히고, 이름·HP·**큰 약점 아이콘** 사선 패널. 나머지 적은 최소 표시 |
| 컷인 | **스킬·브레이크·전원 패링 반격에만.** 사선 띠 + 초상 + 기술명(Gasoek One)이 잉크 획과 함께 0.6초 내외. 턴 시작은 카드가 튀어나오는 것으로 끝 |
| 타이밍 링 | 모양은 단순한 원 유지(가독성). 기준 링 = 뼈색 + 먹 외곽선, 조여드는 링 = **진홍(적 공격 · 패링)** / **금(내 스킬 · QTE)** |
| 판정 결과 | 색을 늘리지 않고 밝기·크기·잉크로: Perfect·Parry = 밝은 금 + 굵게 + 크게 터짐 + 잉크 얼룩, Good·Dodge = 금 보통, Miss = 뼈색 점선이 깨지듯 흩어짐, 피격 = 진홍 점선 |

구현: `src/battle/battleUI.ts` + `src/battle/battleUI.css`. 톱니(SVG), 칼날 표식(SVG), 잉크 띠·튀김(CSS/SVG)은 2D 에셋이 오기 전까지의 대체물이다.
전투 화면에는 이전 스타일 요소가 남아 있지 않다.

### 9-2. 이후 화면
모든 화면이 새 스타일로 바뀌었다. 새 화면을 만들 때는 작업 전에 사용자에게 구도를 묻는다.

### 9-3. 협상

| 요소 | 결정 |
|---|---|
| 구도 | **대면.** 상대 초상이 화면 오른쪽에 큰 사선 창(330×420)으로 들어오고, 대사는 왼쪽 아래 사선 띠. 이름은 띠 위에 금 반전 탭. 대사 문장은 수평 |
| 전투 HUD | 협상 동안 **숨김**(파티 카드·턴 순서·적 이름표). 끝나면 돌아옴 |
| 대답 선택지 | **펼쳐진 패(부채꼴).** 띠 위로 칼날 카드 2~3장이 부채처럼 펼쳐짐. 선택 = 들어 올림 + 금 반전. 좌우(상하도 가능)·숫자키로 고름. 고른 카드는 위로 날아가고 나머지는 접힘 |
| 표정 | 대사에 표정이 있으면 초상 교체 + 반응(happy = 들썩, angry = 흔들림 + 진홍 그늘). 시스템 안내 중엔 초상이 어두워짐 |
| 영입 판정 | **톱니 룰렛.** 이빨 20개 중 확률만큼 금색, 회전하다 바늘 아래 이빨로 성공/실패. 이빨이 지날 때마다 딸깍. 옆에 확률 내역(수평 문장) |
| 은총 | 영입 성공 시 **여신의 깃털**이 떨어짐 — 깃털 언어의 첫 사용처 |

구현: `BattleUI.beginTalk / say / choose / chanceRoll / endTalk` (`negotiation.ts`가 시작 시 `beginTalk`, 모든 종료 경로의 `closeDialog`가 `endTalk`).

### 9-4. 전투 결과 (승리 · 전멸)

| 요소 | 결정 |
|---|---|
| 구도 | **사선 분할.** 왼쪽은 먹색 쐐기(오른쪽 변이 사선, 금 테두리 선)가 밀려 들어오고, 오른쪽은 3D 승리 포즈 위로 멤버 카드가 계단식 사선 배치. 전투 HUD는 숨김 |
| 승리 제목 | Victory (Cinzel Decorative). 별도 VICTORY 배너는 쓰지 않음 |
| 보상 | 쐐기 안에서 **한 줄씩 찍힘**(EXP · 기어 카운트업 · 획득 아이템 · 영입), 줄마다 딸깍 |
| EXP | 카드마다 **사선 게이지가 차오름**. 레벨을 넘으면 비우고 다시 차며, Level Up 태그(+새 스킬) — 레벨업은 깃털(은총). 대기 멤버는 흐리게 + 대기 표시, 6명 이상이면 카드가 작아짐 |
| 넘기기 | 첫 입력은 연출을 끝까지 건너뜀, 다음 입력으로 닫힘 |
| 전멸 | 같은 분할 구도를 **진홍 테두리 + 붉게 가라앉은 장면**으로. Defeated + 원정대가 쓰러졌다, 선택지(다시 도전 / 에테르 샘에서 재시작)는 쐐기 안의 칼날 목록 |

구현: `BattleUI.victoryScreen / defeatScreen`. 데이터는 `battle.ts`의 `finish()`가 `State.giveXp` 전후 값으로 만든다.

### 9-5. 전투 안내 (튜토리얼)

| 요소 | 결정 |
|---|---|
| 형태 | **상황형 한 줄 안내.** 첫 전투 시작 때 문단을 몰아 보여주지 않고, 개념이 처음 나오는 순간 그것 하나만: 첫 커맨드 = AP, 첫 QTE 스킬 = QTE, 첫 적 공격 직전 = Parry(+회피), 첫 브레이크 = Break(다음 턴 경계에), 첫 대화 = Talk |
| 모양 | 화면 위쪽 먹색 사선 띠(금 위아래 선) + 왼쪽에 영어 제목(Cinzel Decorative), 오른쪽에 수평 한두 문장과 실제 버튼 표기(입력 장치에 따라 바뀜). 뒤 장면은 어둡게 |
| 진행 | **게임이 멈추고 확인을 기다림.** 0.4초 동안은 입력을 받지 않아 누르고 있던 키로 넘어가지 않음. 떠 있던 배너는 치움 |
| 다시 보기 | 메뉴 → 조작법 → 전투 안내 다시 보기 (본 안내 목록 `State.tipsSeen`을 비움) |

문구: `src/battle/tips.ts`. 새 개념을 넣을 때는 여기에 한 줄 안내를 추가하고, 그 개념이 처음 나오는 지점에서 `Battle.tip(id)`을 부른다.

### 9-6. 필드 HUD
