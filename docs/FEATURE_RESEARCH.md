# 기능 조사 — 프로토타입 다음 단계 후보

> 작성: 2026-10. 참고작 3편(하늘의 궤적 1st Chapter 리메이크 · Clair Obscur: Expedition 33 · 진 여신전생/페르소나)과 그 밖의 RPG에서 **우리 루프(필드 액션 → 패링 턴제 → 협상 영입)에 붙일 만한 기능**을 골라 정리한 문서.
> 여기 적힌 이름·연출·수치는 전부 **제안**이다. 채택할 항목과 이름·톤은 구현 전에 정한다.

---

## 0. 지금 빌드에 있는 것 / 비어 있는 것

| 있음 | 비어 있음 (참고작 대비) |
|---|---|
| 필드 브레이크 → 선제/공평/기습 진입 | **세이브/로드** (새로고침하면 처음부터) |
| CTB 턴 순서, AP, 스킬 QTE, 패링/회피, 전부 패링 시 반격, 브레이크 | 장비·빌드 요소 (스탯은 레벨로만 결정) |
| 속성 5종 + 약점/내성, 도감의 `known`(발견한 상성) | 캐릭터별 고유 전투 메커니즘 |
| 협상(성격·질문·요구), 패링 횟수 → 영입 확률 | 몬스터 **합체/계승**, 영입 몬스터 성장 경로 |
| 중복 영입 = 경험치 흡수 | 상점·제작·돈(기어) 쓸 곳 |
| 아이템 4종, 상태이상 7종 | 퀘스트·목표, 지역 2개 이상, 보스 |
| 휴식 지점(전체 회복 + 적 재배치) | 캠프 대화·동료 관계 |

`money`(기어)는 협상 요구에만 쓰이고, 몬스터 `drops`도 소모품뿐이라 **전투 보상을 쓸 곳이 거의 없다**. 아래 후보 상당수가 이 빈자리를 메우는 방향이다.

## 1. Clair Obscur: Expedition 33 (전투의 직계 참고작)

### 1-1. 픽토스 / 루미나 — 장착형 패시브 + 영구 습득 ★★★
- **원작**: 캐릭터당 픽토스 3개 장착. 픽토 하나에 스탯 보정 2개 + 특수 효과 1개(예: 완벽 회피 시 AP +1). 장착한 채로 전투 4번 이기면 그 효과를 **루미나**로 익혀, 이후엔 슬롯 없이 루미나 포인트를 내고 누구에게나 붙일 수 있다.
- **우리 적용**: "부품(가칭)" 3칸. 효과는 지금 있는 시스템에 훅을 거는 것만으로 만들 수 있다.
  - 패링 성공 시 AP +1 / 완벽 패링 시 HP 5% 회복 / 반격 피해 +50%
  - 브레이크된 적에게 피해 +25% / 브레이크 수치 +20%
  - 협상 시작 시 호감 +1 / 요구 기어 −30%  ← **협상 루프에 붙는 픽토**는 우리만의 색
  - 전투 시작 시 가속 1턴 / 선제 진입 시 AP +2
- **왜 좋은가**: 몬스터 드롭·보물상자·상점의 보상이 생기고, 빌드 다양성이 생긴다. "4번 이기면 습득"은 같은 부품을 여러 캐릭터가 돌려 쓰는 동기.
- **범위**: `data/parts.ts` 신규, `state.ts`(장착/습득 카운트), `battle.ts`에 이벤트 훅(onParry, onBreak, onTurnStart…), 메뉴 탭 1개. **M**

### 1-2. 그라디언트 게이지 — 쌓아 쓰는 합동/필살기 ★★
- **원작**: 스킬을 쓸 때마다 공유 게이지가 차고(최대 3칸), 1~3칸을 써서 **턴을 소비하지 않는** 강력한 기술을 쓴다.
- **우리 적용**: 패링·QTE Perfect로 채우는 "증기압 게이지". 3칸 소모로 카이+리라 **연계기**(하늘의 궤적 S크래프트 자리에도 대응). 영입 몬스터와의 연계기는 콘텐츠 확장 포인트.
- **범위**: `battle.ts`(게이지, 끼어들기 타이밍), `battleUI.ts`, 연출. **M**

### 1-3. 점프 회피 / 그라디언트 카운터 — 방어 입력 다양화 ★★
- **원작**: 패링·회피 외에 **점프**로만 피할 수 있는 공격(지면 충격파), 그리고 특정 대형 공격에만 쓰는 별도 반격 입력이 있다.
- **우리 적용**: `EnemyMove`에 `defense: 'parry' | 'jump' | 'any'` 필드. 증기 골렘 바닥 내려치기 = 점프 전용. 패링 하나만 연타하는 단조로움을 깬다.
- **범위**: `data/units.ts`, `timing.ts`, 패드/키 매핑, 점프 애니(rig). **S~M**

### 1-4. 자유 조준 사격 ★
- **원작**: 턴 중 카메라를 1인칭으로 돌려 적의 약점 부위를 직접 쏜다(별도 자원 소모).
- **우리 적용**: 리라 전용 "에테르 조준" — 골렘의 노출된 보일러 코어 같은 **약점 부위**를 쏘면 브레이크 대량. 3D 모델의 노드 이름(ASSET_SPEC)으로 부위 판정 가능.
- **범위**: 카메라 모드, 레이캐스트, 모델별 약점 노드 정의. **M~L** (연출 비중이 큼)

### 1-5. 캐릭터별 고유 메커니즘 ★★★
- **원작**: 루네(속성 얼룩을 쌓아 소모), 마엘(자세 전환: 공격/방어/명인), 시엘(예지 스택 → 황혼), 모노코(쓰러뜨린 적의 기술 습득), 베르소(완성도 랭크).
- **우리 적용 예**:
  - **카이 — 열압(Heat)**: 스킬마다 열이 쌓이고, 100%에서 '과열' 상태(피해↑, 매 턴 HP 소모). 패링 성공 시 열 방출. → 이미 있는 `overheat_storm` 이름과도 맞는다.
  - **리라 — 회로 각인**: 속성 마법을 쓰면 그 속성 문양이 남고, 서로 다른 문양 2개를 소모해 상위 마법(번개+냉기 = 초전도 등).
  - **영입 몬스터**: 성격(PersonalityId)에 따른 고유 패시브. 겁쟁이는 HP 낮을 때 회피율↑, 기사도는 아군 대신 맞기 등.
- **범위**: 캐릭터당 **S~M**. 전투 깊이를 가장 싸게 늘리는 축.

### 1-6. 원정대 깃발(캠프) — 휴식 + 동료 대화 ★★
- **원작**: 깃발에서 회복·성장 배분·저장, 그리고 동료와 대화하며 관계 레벨이 오르고 새 기술이 열린다.
- **우리 적용**: 지금 휴식 지점에 **저장 + 동료 대화**를 더한다. 영입 몬스터도 성격별 대사가 이미 있으므로(`data/negotiation.ts`) "친밀도"를 붙이기 쉽다. 친밀도 MAX → 연계기 해금(1-2와 연결).
- **범위**: 세이브(아래 4-1) 이후 **M**.

## 2. 하늘의 궤적 1st Chapter (필드의 직계 참고작)

리메이크는 실시간 필드 액션과 턴제 커맨드 전투를 오가며, 작은 적은 필드에서 처치하고 큰 적은 기절시켜 턴제로 넘어간다 — 우리 필드 구조가 정확히 이것이다.

### 2-1. 오브먼트 / 쿼츠 — 슬롯 + 라인으로 마법 해금 ★★★
- **원작**: 캐릭터마다 오브먼트에 쿼츠를 끼워 스탯을 올리고, **같은 라인에 놓인 쿼츠의 속성 수치 합**이 기준을 넘으면 마법(아츠)이 열린다. 슬롯은 처음 2개에서 시작해 재료(셉티스)로 개방.
- **우리 적용**: 1-1 픽토스와 **둘 중 하나**를 택하는 게 맞다(역할이 겹친다). 차이점:
  - 픽토스 = 효과 중심(플레이 방식이 바뀜), 쿼츠 = 속성 수치 중심(쓸 수 있는 **마법**이 바뀜)
  - 쿼츠식은 "리라가 어떤 속성 마법을 쓰느냐"를 플레이어가 고르게 하고, 몬스터 약점 상성(번개·냉기 편중)과 직결된다.
  - 몬스터를 쓰러뜨리면 나오는 **속성 결정**(셉티스 자리)으로 슬롯 개방 → 기어 외의 두 번째 재화.
- **추천**: 패링·협상과 맞물리는 효과가 많은 **픽토스식을 기본**으로, 쿼츠의 "속성 수치로 마법 해금"만 리라에게 부분 차용.

### 2-2. 턴 순서 보너스(AT 보너스) ★★★ — 가장 저렴한 고효율 후보
- **원작**: 턴 순서표의 특정 칸에 보너스(회복, 크리티컬, 증기 추가 등)가 붙어 있어, 속도·지연기로 **누가 그 칸을 먹느냐**를 다툰다.
- **우리 적용**: 이미 CTB 순서표가 있다. 칸마다 확률로 `HP+10%`, `AP+2`, `크리티컬`, `브레이크+` 아이콘을 붙이고, 적이 그 칸을 가져가면 적이 받는다. **지연(턴 밀기)** 효과 스킬 1~2개를 추가하면 바로 전략성이 생긴다.
- **범위**: `battle.ts` 순서 계산, 턴 순서 UI 아이콘. **S**

### 2-3. 전술 보너스 배율 ★★
- **원작**: 반격 여러 번, 약점 공략, 인터럽트, 저체력 승리 등을 하면 전투 결과 보상 배율이 오른다.
- **우리 적용**: 결과 화면에 "완벽 패링 ×3, 약점 공략, 무피해" 등 항목별 보너스 → 경험치/기어 배율. 패링 숙련을 보상으로 연결.
- **범위**: 결과 집계 + 결과 UI. **S**

### 2-4. 유격사(Bracer) 의뢰 게시판 ★★
- **원작**: 길드 게시판에서 의뢰를 받고, 완료하면 보수 + 유격사 랭크(BP)가 오른다.
- **우리 적용**: 휴식 지점 옆 게시판. "톱니쥐 3마리 영입", "태엽 기사를 패링 0회 실수로 쓰러뜨리기", "시계탑에서 X 조사" 같은 의뢰. **협상·영입을 의뢰 목표로 쓸 수 있다**는 점이 차별점. 맵 1개로도 콘텐츠량이 늘어난다.
- **범위**: `data/quests.ts`, 진행 플래그, 필드 HUD 추적. **M**

### 2-5. 요리·수첩·낚시 등 생활 요소 ★
- 요리(재료 → 회복/버프 음식, 레시피 수집), 수첩(인물·몬스터·의뢰 기록), 낚시 미니게임.
- 우리 쪽에선 **도감 강화**(발견한 상성 외에 협상 기록·좋아하는 대답 기록)가 가장 맞다. 요리는 "증기 조리기"로 세계관 맞춤 가능하지만 우선순위 낮음.

## 3. 진 여신전생 / 페르소나 (영입의 직계 참고작)

### 3-1. 악마 합체 ★★★ — 영입 시스템의 핵심 확장
- **원작**: 동료 악마 둘을 합쳐 상위 종족을 만들고, 재료의 스킬 일부를 **계승**한다. 도감에 등록한 악마는 돈을 내고 다시 불러낸다.
- **우리 적용**: "공방(가칭)에서 몬스터 조립". 지금은 중복 영입이 경험치 흡수로 끝나는데, 여기에 **합체 → 새 종족** 경로를 더한다.
  - 예: 톱니쥐 + 램프 위스프 → (신규) 태엽 등불쥐, 재료 스킬 1개 계승
  - 도감 재소환: 기어 소모 → **기어의 용처가 생김**
- **주의**: 종족이 6종뿐이라 합체표가 성립하려면 몬스터 수가 늘어야 한다(신규 모델 비용). 초기엔 "스킬 계승만"(몬스터 A를 B에 흡수시키며 스킬 1개를 물려줌)으로 축소 구현 가능 — 기존 흡수 규칙의 자연스러운 확장.
- **범위**: 축소판 **S~M**, 정식 합체 **L**(콘텐츠 포함).

### 3-2. 프레스 턴 → "약점 = 추가 행동" ★★
- **원작**: 약점을 찌르거나 크리티컬을 내면 행동 아이콘을 반만 소모(추가 행동), 빗나가거나 무효면 아이콘을 더 잃는다. **적도 같은 규칙**.
- **우리 적용**: CTB를 버리지 않고 "약점 타격 시 다음 턴이 빨리 돌아옴(턴 순서 앞당김)" 정도로 차용. 2-2 AT 보너스·지연과 같은 축에서 동작해 구현이 겹친다.
- **범위**: **S**

### 3-3. 페르소나식 홀드업 / 총공격 ★★★ — 브레이크와 협상을 잇는 다리
- **원작(페르소나 5)**: 적 전원을 다운시키면 "홀드업" → 총공격 / 협상(영입·돈·아이템) 중 선택.
- **우리 적용**: **적 전원이 브레이크 상태가 되면** 선택지: ① 총공격(파티 전체 연출 공격) ② 포위 협상(협상 확률 대폭↑, 요구 거절 불가) ③ 갈취(기어/아이템). 우리 게임의 세 축(브레이크·패링·협상)을 하나의 순간으로 묶는 기능이라 테마 적합도가 가장 높다.
- **범위**: `battle.ts`(조건 판정), 협상 진입 경로 재사용, 총공격 연출. **M**

### 3-4. 협상 확장 ★★
- 원작 요소 중 아직 없는 것:
  - **동료 몬스터가 협상에 끼어들기**: 같은 성격/종족 동료가 있으면 호감 보정, 대사 추가
  - **적이 "아는 사이"**: 이미 영입한 종족이면 바로 합류/정보 제공
  - **협상 결렬 패널티 다양화**: 도망·동료 부르기·기습
  - **문 하나 열어 주기**: 협상 결과로 아이템 대신 "의뢰 정보"나 "숨은 보물 위치"
- **범위**: 대부분 `data/negotiation.ts` + `battle/negotiation.ts`. **S** 단위로 쪼개 넣기 쉬움.

### 3-5. 스킬 습득(악마의 속삭임) ★
- 영입 몬스터가 레벨업하면 새 스킬을 배우거나 플레이어 쪽에 스킬을 남겨 주는 구조. 지금 몬스터 `allySkills`는 고정 2개라, **레벨 조건이 붙은 3번째 스킬**만 추가해도 성장감이 생긴다. **S**

## 4. 그 밖의 RPG에서 가져올 만한 것

### 4-1. 세이브/로드 — 필수 ★★★
- 지금 없음. 위 대부분의 기능(관계, 의뢰, 장비, 합체)은 저장이 없으면 검증 자체가 어렵다.
- `GameState`가 이미 직렬화하기 쉬운 형태(배열·Record·Set)다. `localStorage` 슬롯 3개 + 휴식 지점에서 저장(+ 자동 저장)으로 시작.
- **범위**: `state.ts` toJSON/fromJSON, 타이틀 "이어하기", 메뉴. **S**

### 4-2. Sea of Stars — 타이밍 콤보 + 잠금(Lock) 깨기 ★★
- 적이 대기 행동을 할 때 머리 위에 **속성 자물쇠**가 뜨고, 그 속성으로 다 깨면 행동이 취소된다.
- 우리 적용: 적의 **강력한 기술 예고(차지)** 중에 약점 속성으로 N회 때리면 기술 취소 + 브레이크. 적의 다음 행동이 보이니 턴 순서 고민이 생긴다. **S~M**

### 4-3. 옥토패스 트래블러 — 실드/부스트 ★
- 적 머리 위에 숨겨진 약점 칸 + 실드 수치, 플레이어는 BP를 모아 한 번에 몰아 쓴다. 우리는 이미 브레이크 게이지·AP가 있어 대부분 겹친다. "**약점이 ?로 가려졌다가 맞혀야 드러남**"만 도감 `known`과 연결해 UI로 보여 주는 정도 추천.

### 4-4. 메타포: 리판타지오 — 필드 일격 + 분대 전투 ★
- 필드에서 약한 적은 바로 처치, 강한 적은 기절시키고 진입 — 이미 우리에게 있음. 참고할 점은 **레벨 차가 크면 필드 공격만으로 자동 승리**(보상 수령)하는 편의 기능. 반복 사냥 피로를 줄인다. **S**

### 4-5. 드래곤 퀘스트 몬스터즈 / 포켓몬 — 몬스터 육성 깊이 ★
- 개체 성격·특성, 배합(합체) 시 능력치 일부 계승, 몬스터 전용 장비. 3-1 합체를 정식으로 할 때 참고.

### 4-6. 파이널 판타지 X — CTB 행동 미리보기 ★★
- 스킬을 고를 때 **그 스킬을 쓰면 턴 순서가 어떻게 바뀌는지** 미리 보여 준다. 우리 CTB에 바로 붙일 수 있고, 2-2/3-2(턴 조작 계열)를 넣으면 거의 필수가 된다. **S**

### 4-7. 접근성 · 편의
- 전투 배속(×2), 연출 스킵, 자동 전투(약한 적), 패링 자동 보조 옵션(스토리 난이도). 33원정대·궤적 리메이크 모두 기본 제공. **S** 단위.

## 5. 추천 로드맵

우선순위 = (루프 적합도 × 플레이 체감) ÷ 비용. 신규 3D 모델이 필요한 항목은 뒤로 미뤘다.

| 단계 | 항목 | 이유 |
|---|---|---|
| **A. 기반** | 4-1 세이브/로드 · 2-3 전술 보너스 · 4-7 배속 | 이후 모든 기능 검증의 전제. 각 S |
| **B. 전투 깊이** | 2-2 턴 순서 보너스 + 4-6 CTB 미리보기 · 1-5 카이 열압/리라 회로 · 1-3 점프 회피 | 기존 CTB·패링에 얹기만 하면 됨. 새 에셋 거의 없음 |
| **C. 세 축 연결** | 3-3 전원 브레이크 → 홀드업(총공격/포위 협상) · 3-4 협상 확장 | 브레이크·패링·협상을 하나로 묶는 우리만의 순간 |
| **D. 빌드/보상** | 1-1 부품(픽토스식) · 3-1 축소판 계승 · 3-5 몬스터 3번째 스킬 | 기어·드롭에 용처가 생김 |
| **E. 콘텐츠** | 2-4 의뢰 게시판 · 1-6 캠프 대화/친밀도 · 1-2 연계기 · 두 번째 지역/보스 | 플레이 시간 확장. 대사·2D 에셋 비중 큼 |

> 다음 한 걸음으로는 **A + 2-2(턴 순서 보너스)**를 추천. 작업량이 작고, 세이브가 생기면 이후 기능을 반복 테스트하기 쉬워진다.

## 6. 구현 전에 정해야 할 것

UI 바이블에 없는 취향 결정이라 착수 전에 확인이 필요하다.

1. **빌드 시스템 방향**: 픽토스식(효과 중심) vs 쿼츠식(속성·마법 중심) vs 혼합
2. **이름**: 장착 부품, 연계 게이지, 합체 공방, 홀드업 등의 세계관 명칭
3. **홀드업 연출 강도**: 페르소나식 과장된 컷인 vs 지금 잉크 칼획 톤에 맞춘 절제된 연출
4. **새 몬스터 추가 의향**: 합체를 정식으로 하려면 종족 수가 늘어야 함(Blender 모델 + 2D 초상 비용)
5. **세이브 방식**: 휴식 지점에서만 저장 vs 아무 데서나 + 자동 저장
